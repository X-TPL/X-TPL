# X-TPL Build Pipeline

This pipeline collects open-source Android apps from GitHub, builds them using Docker, and analyzes their third-party library (TPL) dependencies. It covers four frameworks: **Flutter**, **React Native**, **Cordova**, and **MAUI**.

## Pipeline overview

```
crawler.py  →  process_repos.py  →  analyzer.py  →  orchestrator.py  →  analyze_tpls.py
  (crawl)        (download)          (manifest)        (build APKs)       (TPL report)
```

The combined chart across all frameworks is generated by `scripts/combined_chart.py`.

---

## System requirements

| Tool | Minimum version | Notes |
|---|---|---|
| Python | 3.10+ | Required for `str \| None` type syntax |
| Docker Engine | 24+ | The orchestrators call `docker` as a subprocess |
| Git | any | Used inside Docker images |

The pipeline is designed to run on **Linux** (Ubuntu). The storage paths and Docker cache mounts assume a Linux environment.

## Python packages

Install once, globally or in a virtualenv:

```bash
pip install \
  pygithub>=2.8 \
  python-dotenv>=1.0 \
  requests>=2.32 \
  pyyaml>=6.0 \
  packaging>=24 \
  matplotlib>=3.8
```

`matplotlib` is only needed for chart generation (`analyze_tpls.py` and `combined_chart.py`). The scripts skip it gracefully if missing.

## Environment configuration

All secrets and machine-specific paths live in a single `.env` file at the repo root (gitignored). Copy the template and fill in your values:

```bash
cp .env.example .env
```

```
TOKEN=ghp_your_personal_access_token_here

STORAGE_ROOT_FLUTTER=/home/ubuntu/storage/assets
STORAGE_ROOT_RN=/home/ubuntu/storage/rn_assets
STORAGE_ROOT_CORDOVA=/home/ubuntu/storage/cordova_assets
STORAGE_ROOT_MAUI=/home/ubuntu/storage/maui_assets
STORAGE_ROOT_UNITY=/home/ubuntu/storage/unity_assets
```

- **`TOKEN`** — a GitHub personal access token used by the crawlers. A classic PAT with no extra scopes is sufficient; fine-grained tokens also work.
- **`STORAGE_ROOT_*`** — one per framework. Each framework's `process_repos.py` downloads and extracts repositories into `<path>/extracted/`, and `analyzer.py` reads from that same location. Both scripts load the same variable, so there is only one path to configure per framework.

Every script that needs these values calls `load_dotenv()`, which searches the current directory and all parent directories for `.env` — so a single file at the repo root is picked up no matter which framework directory you run scripts from. Scripts fail fast with a clear error if a required variable is missing.

Create the storage directories before running (the `extracted/` subfolder is created automatically by `process_repos.py`):

```bash
mkdir -p /home/ubuntu/storage/{assets,rn_assets,maui_assets,cordova_assets,unity_assets}
```

## Docker cache directories

The orchestrators mount host directories into containers to cache dependencies between builds. Create them in advance to avoid re-downloading everything on each run:

```bash
mkdir -p ~/.pub-cache        # Flutter
mkdir -p ~/.npm              # React Native, Cordova
mkdir -p ~/.gradle           # React Native
mkdir -p ~/.nuget/packages   # MAUI
```

## Running the pipeline

All commands are run from the relevant framework directory (e.g. `scripts/flutter/`).

### Step 1 — Crawl GitHub for repositories

```bash
cd scripts/flutter && python crawler.py
```

Writes `repos.json` with repository metadata. Repeat for each framework directory.

Each `crawler.py` defines two constants at the top of the file:

- **`TARGET_BUILDABLE`** — the crawl stops once this many "buildable" repos (i.e. repos that pass the framework's heuristic checks, e.g. containing a `pubspec.yaml`/`package.json`/`.csproj`) have been collected. `1000` for all frameworks.
- **`BATCH_SIZE`** — how many repos are scanned per GitHub search page before the `pushed:<timestamp>` cursor advances to the next page. `1000` for all frameworks (the GitHub Search API maximum per query).

Lower `TARGET_BUILDABLE` to do a quick test run, or raise it to collect a larger dataset.

### Step 2 — Download repositories

```bash
cd scripts/flutter && python process_repos.py
```

Reads `repos.json`, downloads and extracts each repository to the storage directory.

### Step 3 — Generate build manifest

```bash
cd scripts/flutter && python analyzer.py
```

Scans the extracted repositories, determines build parameters (Flutter/Node/.NET version, JDK version), and writes `build_manifest.yaml`.

### Step 4 — Build APKs

```bash
cd scripts/flutter && python orchestrator.py
```

Reads `build_manifest.yaml` and builds each app inside a Docker container. Docker images are built automatically on first use and reused thereafter. Output APKs and lock files are written to `output/<app-id>/`.

**Note:** Docker images are large (several GB each). The first build per framework takes 10–30 minutes depending on bandwidth, as it downloads the SDK, Android tools, and dependencies.

### Step 5 — Analyze TPL dependencies

```bash
cd scripts/flutter  && python analyze_tpls.py
cd scripts/RN       && python analyze_tpls.py
cd scripts/maui     && python analyze_tpls.py
cd scripts/cordova  && python analyze_tpls.py
```

Parses the lock files from `output/` and writes:
- `tpl_analysis.txt` — direct/transitive split, top 10 libraries, ASCII histogram
- `tpl_chart.pdf` — bar chart of the top 20 most used libraries

### Step 6 — Generate combined chart

```bash
cd scripts && python combined_chart.py
```

Reads all framework output directories and writes `scripts/combined_chart.pdf` with a rank-frequency distribution panel for each framework.
